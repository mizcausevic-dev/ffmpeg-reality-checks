### Description

You encode with B-frames and ffprobe prints a negative dts, N/A, or three different times for the same picture. Which timestamp is true, and which one does each tool print? We encode 50 synthetic frames with libx264 -bf 2 and read them four ways.

Clip (lavfi testsrc2, 64x48, 25 fps, 50 frames, libx264 with b-adapt 0 and scenecut 0, so the pattern is fixed): bf2.mp4, bf2.mkv (stream copy), bf2neg.mp4 (stream copy with -movflags +negative_cts_offsets), and a control with -bf 0 in mp4 and mkv. The 5 files hold the same 50 pictures (identical frame hashes).

Readers: ffprobe packets (pts, dts), ffprobe decoded frames (pts, pkt_dts, best_effort_timestamp), the showinfo filter, and the container bytes in Node (mp4 stts, ctts and elst; matroska block times).

Control: with -bf 0, dts equals pts on all 50 packets in mp4 and in mkv, and every reader gives the same time for every picture.

With -bf 2 in mp4 the first packet has pts 0.00 s and dts -0.08 s (2 frames, has_b_frames 2). dts rises 0.04 s per packet, never passes pts, and pts is not monotonic in file order (0.00, 0.12, 0.04, 0.08, 0.24). The format and stream start_time are still 0.00 s.

The negative number is not in the file. The mp4 stores decode time 0 for the first sample, a composition offset of 1024 ticks (time scale 12800 = 0.08 s) and an edit list with media time 1024. ffprobe shows stored dts minus the edit list. Known positive: with -ignore_editlist 1 the first dts is 0.00 s and the first pts is 0.08 s. All 50 shown pts and dts match a model built from the bytes.

Decoded frames: best_effort_timestamp equals pts on 50 of 50 frames, and showinfo prints the pts of the 50 frames (no dts). But the pkt_dts printed on a frame is not the dts of its own packet: it differs on all 48 frames that have one, and the last 2 frames have none.

Same pictures, three answers: the first packet dts is -0.08 s in bf2.mp4, N/A in bf2.mkv (matroska stores one whole millisecond time per block and no dts; ffprobe rebuilds it and prints N/A for the first 2 packets) and -0.04 s in bf2neg.mp4 (signed ctts, edit list media time 0). The pts are identical in all three.

The 10 tests pass on ffmpeg 6.1.1.
