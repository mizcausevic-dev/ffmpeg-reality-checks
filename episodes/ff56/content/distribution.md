### Description

You copy a file into MP4 with -map 0 and ffmpeg says: could not find tag for codec. Which stream is the problem? We copy ten stream types into MP4 with -c copy, one at a time, and read the stream list before and after.

Source (lavfi, x264, mkv, 96x72, 25 fps): 2 seconds, 50 video frames, plus one extra stream per source: five audio codecs (aac, opus, flac, pcm_s16le, vorbis), a one frame mjpeg cover picture, three subtitle formats (subrip, ass, webvtt with two cues, "hello one" and "hello two"), and a 32 byte attachment labelled ttf (synthetic bytes, not a real font).

Readers: ffprobe (the stream list of the source and of the output, and whether the output opens at all) and the MP4 file read in Node (is there a moov box, then each track's handler type and sample entry), plus a byte search for the subtitle text. Video frames are compared by ffmpeg framemd5 against the source.

Control: video, five audio codecs and the cover picture in one file with -map 0 -c copy: 7 streams in, 7 out, moov box present, ffprobe opens it, the 50 video frame hashes equal the source's.

Six of ten pass: aac, opus, flac, pcm_s16le, vorbis and the cover picture (which becomes a second video track). In each, the stream list after equals the list before and the video frames are the same 50 hashes. Four of ten fail: subrip, ass, webvtt and the ttf attachment. Each prints "Could not find tag for codec ... in stream #1", exits non zero and leaves a 0 byte file: no moov box, and ffprobe cannot open it. The video was never the problem.

In one file with video, five audio, subrip and the attachment (8 streams), half fixes fail one by one. -map 0 -c copy fails at subrip (stream 6). Adding -c:s mov_text fails next at the ttf attachment (stream 7). -map 0 -sn fails at the attachment (stream 6). -map 0 -map -0:t fails at subrip (stream 6). Four tries, four 0 byte files.

Both together work: -map 0 -map -0:t -c copy -c:s mov_text gives 7 streams (video, five audio, mov_text), and the cue text is found in the file bytes and in a decode by ffmpeg. Alone, each of subrip, ass and webvtt converts to mov_text, and the attachment copies with -map -0:t. Or -map 0:v -map 0:a -c copy gives 6 streams and no subtitle.

Without -c copy: subrip fails differently ("Automatic encoder selection failed", no output file), ttf fails the same way, and aac re-encodes, so its video frame hashes differ from the source.

The 13 tests pass on ffmpeg 6.1.1; 8.1.2 pending.
