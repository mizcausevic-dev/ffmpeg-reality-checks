### Description

You asked FFmpeg for 3 seconds starting at 7.5. You added -c copy so it would be instant. It was instant. But was it the clip you asked for?

We build a synthetic 20 second test video: 25 frames a second, a keyframe every 5 seconds, and lossless frames so every one of the 500 frames has its own fingerprint. That lets us ask a precise question: which source frame does the clip begin on?

With -ss before -i, the clip starts on frame 188 (7.52 s) and holds 75 frames. Correct. But the file contains 138 packets, not 75: 63 frames of hidden pre-roll that FFmpeg keeps so the first frame can decode. With the same flag moved after -i, the clip starts on frame 250 (10.00 s) and holds 13 frames. Half a second, not three.

The reason: a stream copy decodes nothing, and most frames store only what changed since an earlier frame, so a copied clip can only begin on a keyframe. Before -i, FFmpeg goes back to the keyframe at 5 s and hides the extra with an edit list. After -i, it discards packets until the next keyframe, at 10 s. Re-encoding starts on frame 188 and gives 74 frames. If you must copy, check the result with ffprobe instead of trusting the command line.
