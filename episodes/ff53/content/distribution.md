### Description

Does libx265 at the same CRF give the same quality as libx264? We encode one synthetic clip with both at CRF 18, 23 and 28 on ffmpeg 6.1.1, then read back the file size, PSNR and SSIM against the source.

Clip (lavfi, testsrc2 with temporal noise, 320x240, 25 fps, 75 frames, 3 s), stored lossless and used as the reference. Both encoders use preset medium, yuv420p, one thread for x264 and one frame thread with no pool for x265, so the files are repeatable. Also encoded with no -crf at all (the encoders' own defaults).

Readers: (1) ffmpeg's psnr and ssim filters; (2) Node, with PSNR and SSIM written from scratch on decoded yuv420p frames (Y plane, PSNR as the mean of per-frame MSE, SSIM with an 8x8 window and stride 4). The file size is read from disk and from ffprobe.

Control: x264 with -qp 0 (lossless) reads PSNR infinite and SSIM 1.0 in both readers.

Results: at CRF 18, x265 is 494944 bytes against 819510 for x264 (39.6% smaller), but its PSNR Y is 0.59 dB lower (38.35 against 38.94) and SSIM Y is 0.9039 against 0.9270. At CRF 23 it flips: x265 is 127679 bytes against 123693 (3.2% bigger) and 0.33 dB higher (37.14 against 36.81). At CRF 28 the files are the same size (62813 against 62946 bytes, 0.2% smaller) and x265 is 0.49 dB higher (35.41 against 34.92). The two readers agree on all eight encodes (largest PSNR difference 3.9e-7 dB, largest SSIM difference 4.1e-7), and a second CRF 23 encode with each codec is byte for byte identical. In both codecs a lower CRF gives more bytes and a higher PSNR.

Defaults: with no -crf, libx264 writes exactly the CRF 23 file and libx265 exactly the CRF 28 file (same hashes). So out of the box x265 is 49.2% smaller and 1.40 dB lower in PSNR Y (35.41 against 36.81).

Measured on ffmpeg 6.1.1; 8.1.2 pending (libx264 core and libx265 version may differ in that build, so the byte counts may too). The 13 tests pass on ffmpeg 6.1.1.
