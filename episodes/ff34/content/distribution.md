### Description

You turn 100 numbered PNGs into a video with a 10 fps rate and the film is far too short. -framerate and -r both set a rate, so what is the difference? It depends on where you put them. We mark every picture and count which frames survive.

Source (lavfi): 100 PNGs, img001.png to img100.png, 64x64 8 bit gray. File number N has gray level 2N + 10, so every picture carries its own id. Control with no option: the default input rate is 25 fps, so 100 frames last 4.0 s and every frame appears once.

Readers: ffprobe (packet count, r_frame_rate, last packet timestamp plus duration) and a decode (frame md5 matched to the source PNGs, decoded pixel values). They agree on every output.

Before the input: -framerate 10 -i gives all 100 frames once, in order, in 10.0 s. -r 10 -i gives exactly the same frames and 10.0 s. -framerate 25 -r 10 -i: the -r value wins, 10.0 s. -pattern_type glob changes nothing.

After the input: -i img%03d.png -r 10. The input still runs at 25 fps, so ffmpeg converts 25 to 10. Only 42 of the 100 frames survive (1, 2, 3, 5, 8, 10, ...), 58 are dropped, none repeated, and the film lasts 4.2 s.

-framerate 10 -i img%03d.png -r 30 keeps all 100 frames, repeats each 3 times: 300 frames, 10.0 s. If the files start at img051.png, the command fails without -start_number 51; with it you get 50 frames, 5.0 s.

The 14 tests pass on ffmpeg 6.1.1.
