# FF74 distribution kit: FFmpeg loop Filter: loop=2 Plays 3 Times, start=10 Begins at Frame 9

All numbers below come from the synthetic fixture in `episodes/ff74/fixture/` (experiment.mjs, run.mjs) and its tests, measured on ffmpeg 6.1.1; the tests also pass on 8.1.2 (Windows full build). Exact numbers are asserted on 6.1.1 only where the film says so; on other builds the tests assert relations.

### Description

You loop a few frames with the loop filter and the output is not what you wrote. Is size in frames or seconds? Does loop=2 play the frames two times or three? Which frame does start=10 actually repeat? We loop a counter clip and read back which source frame every output frame is.

Bench (lavfi, no real footage): a 50 frame clip, 64x48, 25 fps, every frame a flat card whose luma is 16 plus its frame number, so one decoded frame names itself. The filter is loop=loop=N:size=M:start=S, run on the live source and on a lossless file. Grid: N in 0, 1, 2, 3, M in 1, 5, 25, 100, S in 0, 1, 2, 10, 48: 80 cases, plus time=, start=-1, a start past the end, size=0, three frame rates and loop=-1.

Readers: Node on the raw decoded planes (id = luma minus 16, every frame flat), and ffmpeg framemd5 (every output hash looked up in the hashes of the 50 source frames). They agree on all 80 grid cases and on every extra case. For the duration claims, ffprobe on an FFV1 file written from the same graph. Controls: four sequences built with trim and concat, no loop filter, with repeats chosen in advance (repeat from 9, repeat from 10, a frame played three times, no repeat): both readers return them exactly and tell frame 9 from frame 10.

Plays: loop=0 gives 50 frames, loop=1 gives 55, loop=2 gives 60, loop=3 gives 65 (size=5, start=10). The looped frames play N plus 1 times: loop=2 plays them three times. Loop counts the extra plays.

Size: size is frames. The same filter on clips at 10, 25 and 50 frames per second repeats the same five frames (9 to 13) and gives 55 frames each time, 5.5 s, 2.2 s and 1.1 s long: ffprobe agrees. Size is a maximum: size=100 with start=10 repeats only the 41 frames left, 91 frames out; start=48 with size=5 repeats frames 47 to 49.

Start: on ffmpeg 6.1.1 start counts from 1. start=10 repeats frame 9 first (size=5: 9 to 13), start=0 and start=1 are the same loop from frame 0, start=2 loops from frame 1. A file source gives the same result as the live source (start=10 gives 9 to 13, start=30 with size=3 gives 29 to 31). The time option is compared with the frame time instead: time=0.4 at 25 fps starts at frame 10 exactly. But start defaults to 0, so time=0.4 alone loops from frame 0; with start=30 or start=-1 it starts at frame 10. start=-1 alone, a start past the end of the clip and size=0 (the default) loop nothing: 50 frames out.

Timestamps stay contiguous: 50 frames is 2 s, 60 frames 2.4 s, 100 frames 4 s.

loop=-1: guarded with -frames:v 120 it gives exactly 120 frames (0 to 13, then 9 to 13 again and again). Without the guard the run was still going when it was killed after 3 s.

The 14 tests pass on ffmpeg 6.1.1.

Limits: one clip, 64x48, 25 fps, a lossless counter, ffmpeg 6.1.1. The start rule (start N repeats frame N minus 1) comes from how this build counts frames and is the part most likely to differ on another build. Not tested: other builds, the aloop audio filter, real footage, variable frame rate input, sizes above 100 frames or the 32767 maximum.
