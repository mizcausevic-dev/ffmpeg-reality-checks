### Description

You put an MP4 on your website and it seems to wait before it plays. An MP4 is a list of boxes, so we read the order of the boxes.

We encode one synthetic 10 second clip twice: once plainly, once with -movflags +faststart. Both files hold 250 frames and the same size. The plain file's top-level boxes are ftyp, free, mdat, moov: the index (moov) comes last. With +faststart the order is ftyp, moov, free, mdat. Two independent readers agree on the order: a small parser we wrote, and ffprobe's own trace.

Then ffprobe reads each file from a local HTTP server. A client that cannot seek has to read from the start: for the plain file the server sent every byte (927,238 on ffmpeg 6.1.1), for the faststart file under 50 kB. A client that can use range requests copes with the plain file by jumping to the index: 3 requests instead of 1, one of them starting exactly at the index.

The FFmpeg documentation says faststart runs a second pass, can take a while, and does not work in various situations such as fragmented output, which is why it is off by default.
