### Description

The gif muxer has a -loop option that takes 0, -1 or a count. What do they really mean? We write one synthetic ten frame gif each way on ffmpeg 6.1.1, read the loop block in its bytes, and let ffmpeg's own gif demuxer play each file back.

Clip (lavfi, 32x24, 10 fps, 10 frames, 1.0 s): frame N is a flat card of red level 25 times N, so all 10 frames are different. Written with the gif muxer and -loop set to nothing, -1, 0, 1, 3, 255, 65535 and 65536.

Readers: (1) the file bytes, a GIF block parser in Node that finds the NETSCAPE2.0 application extension and its 16 bit loop count; (2) behaviour, ffmpeg's gif demuxer asked to honour the count (-ignore_loop 0), counting the frames it plays in 20 s. ffprobe gives the frame count and duration as a cross-check (10 frames, 1 s).

Control: a gif built byte by byte in Node, 2 frames of 1x1, loop count 7. The bytes reader says 7 and ffmpeg plays 14 frames from 2, which is 7 passes. With count 0 it keeps playing to the limit; with no loop block it plays once.

Results: -loop 0 writes the NETSCAPE2.0 block with count 0, and leaving -loop out gives the same file, byte for byte (2630 bytes). -loop -1 writes no loop block at all: no NETSCAPE2.0 in the bytes and the file is exactly 19 bytes smaller (2611 bytes); ffmpeg plays it once. -loop 3 writes a count of 3, one byte different from the -loop 0 file, and ffmpeg plays it 3 times (30 frames). -loop 1 writes a count of 1 and ffmpeg plays it once, like -1. 255 and 65535 are written as given; -loop 65536 is refused and nothing is written. The frame hashes are the same for every value, so the loop value is metadata only.

-loop before -i is a different option: on a still png it is the image demuxer's loop, a boolean. -loop 1 there repeats the picture for the 1 s clip and the gif still gets count 0; -loop 3 is not a boolean and ffmpeg refuses.

Measured on ffmpeg 6.1.1. The 12 tests pass on ffmpeg 6.1.1. They also pass on 8.1.2, but there the build-dependent claims (exact counts, bytes, error text) are not asserted, so the film's numbers are 6.1.1 numbers.
