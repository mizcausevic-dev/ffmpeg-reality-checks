### Description

You turned a folder of PNG frames into an MP4 with the simplest FFmpeg command. On some players, a file like that will not play. So what did FFmpeg put inside it?

We build a synthetic source of 50 PNG frames (RGB) and encode it with libx264 at CRF 18 and no pixel format flag. ffprobe reports profile High 4:4:4 Predictive and pixel format yuv444p. FFmpeg kept full color for every pixel because the input had it. Add -pix_fmt yuv420p and ffprobe reports profile High and pixel format yuv420p. As a control, a source that is already yuv420p comes out yuv420p with no flag, so the surprise belongs to RGB input.

Why it matters: 4:2:0 keeps one color sample per 2x2 block of pixels, 4:4:4 keeps one per pixel. The FFmpeg wiki (Encode/H.264) says some players only support 4:2:0 for H.264. We did not test any player; the profile in the file tells you what a player must support.

The fix has a cost. Measured against the original PNG frames with PSNR, the 4:4:4 file scores 37.04 dB and the 4:2:0 file 35.40 dB on this synthetic pattern. How visible that is depends on your picture.
