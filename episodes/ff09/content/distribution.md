### Description

You scale a video to a height with FFmpeg and let it work out the width. It works on most videos and crashes on some. Why? We build synthetic clips and make it fail on purpose.

Control: a 1920x1080 clip with scale=-1:720 becomes 1280x720 and libx264 encodes it: exit code 0, 10 frames on disk.

The crash: a 1000x562 clip with scale=-1:333 becomes 593x333, both odd. libx264 reports "width not divisible by 2 (593x333)". The exit code is not zero (187 on Linux with ffmpeg 6.1.1; Windows with ffmpeg 8.1.2 reports a different large number) and nothing usable is written. The scale filter (read with ffprobe) and the encoder name the same size.

Either dimension is enough. A 640x360 clip scaled to height 240 gives 427x240 (odd width) and fails with a width complaint. scale=-2:333 makes the width even (592) but the height 333 is odd, and it fails with a height complaint.

The fix: make both even. scale=-2:334 gives 594x334, exit 0, 10 frames. The same 593x333 frame encodes fine with -pix_fmt yuv444p, which fits the error being about 4:2:0 chroma. Only libx264 was tested.

Same behavior on ffmpeg 6.1.1 and 8.1.2.
