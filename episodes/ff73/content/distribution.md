### Description

You label a video with drawtext and the text comes out wrong: a percent sign draws nothing, a colon changes the font, an apostrophe vanishes. Is drawtext broken? We draw four short strings, read every frame back, and count the backslashes each one needs.

Bench (lavfi, no real footage): one black gray frame, 768x64, drawtext in DejaVu Sans Mono at size 40 (advance 24 px), white text, one frame out. ffmpeg runs without a shell, so the filter string is exactly what the fixture writes. The strings are 100%, 12:30, it's and a\b, each written after text= with 0 to 9 backslashes in front of the special character, bare and inside single quotes, with expansion on (the default) and with expansion=none: 148 filter strings, 473 ffmpeg runs.

Readers: ffmpeg framemd5 of the output frame against the framemd5 of a reference frame drawn through the clean route (textfile with expansion=none), and Node on the raw pixels, which cuts the frame into 32 cells of 24 px and matches each cell against 94 reference glyphs, with no list of candidates. They agree on all 127 frames reader 2 can read (the other 21: 20 frames drawn in another font, and 1 command that failed). Control: 150 random strings through the clean route read back exactly, 0 mismatches; an untouched frame reads as nothing with 0 ink pixels; it's and its are told apart.

Typed in quotes the obvious way: text='100%' draws a blank frame (0 ink pixels) with exit code 0 and only the warning Stray % near '' on stderr. text='12:30' draws 12 in another font (433 ink pixels): the 30 becomes the next option, the font file, and the frame hash (87ddaf71) is identical to text=12:fontfile=30 and to the build's default font. text='it's' draws its (601 ink pixels, the apostrophe is gone). text='a\b' draws ab.

Fewest backslashes in front of the special character that draw the string exactly (expansion on, bare / quoted; expansion=none, bare / quoted): % 4 / 2 and 0 / 0; : 2 / 1 and 2 / 1; ' 3 / 3 and 3 / 3; \ 8 / 4 and 4 / 2. One backslash for the percent sign changes nothing: quoted, counts 0 and 1 give a blank frame, 2 and 3 draw 100%.

The rule: each of three parsers removes one level of backslash, the filter graph (quotes skip it), the option list, and drawtext's own expansion (expansion=none skips it). A closed form with those three levels predicts all 16 measured minimums.

The clean route: textfile=f.txt:expansion=none draws all four strings exactly with no backslash counting. A textfile alone is not enough: with expansion on, 100% is still blank and a\b is still ab.

Also measured: %{pts} draws the timestamp 0.000000 (2478 ink pixels), not your text; \%{pts} written as above draws %{pts}; an unknown function %{nosuch} draws a blank frame with exit code 0; braces alone are harmless; a bare comma ends the filter (exit code 8, No such filter).

The 15 tests pass on ffmpeg 6.1.1.

Limits: one monospace font (DejaVu Sans Mono), one frame, no shell. On ffmpeg 8.1.2 (Windows build) one thing differs: a bare 12:30 is refused with "No option name near '30'" and a nonzero exit, instead of drawing a wrong frame with exit 0; the backslash counts for the other three strings are the same. The 8.1.2 run used DejaVu Sans Mono too (Consolas has a fractional advance that reader 2 cannot cut into cells). The Stray % behaviour on 6.1.1 (a warning, a blank frame, exit code 0) is the part most likely to differ between builds. Not tested: Windows paths for the font, PowerShell and cmd.exe quoting, bash and zsh quoting layers, filter script files, other fonts, text shaping, enable expressions, real footage.
