### Description

You turn an image into a video with FFmpeg and in some players the colors look a little off. Pure green looks duller. Why? We encode four solid color patches (pure red, green, blue, mid gray) four ways, and read each file back under three readings of the color matrix.

Readers: ffprobe (the color matrix tag the file declares) and a decode to RGB with the value read at the center of each patch.

Plain command (-pix_fmt yuv420p): no color matrix tag, and the pixels were made with BT.601. Read as BT.601 every patch is within 2 levels. Read as BT.709, pure green's green channel falls from 255 to 215, red gains a green channel of 23 and blue gains 14. Gray does not move.

BT.709 pixels with a BT.709 tag read right (within 1 level). Forced to BT.601 they are off by up to 23.

scale=out_color_matrix=bt709 with no -colorspace: on ffmpeg 6.1.1 the file stays untagged and a reader that follows the file assumes BT.601, so it is off by up to 23. On ffmpeg 8.1.2 FFmpeg writes the BT.709 tag itself and the file reads right.

-colorspace bt709 on a plain RGB source: on 6.1.1 it only writes the label (pixels stay BT.601, off by 40). On 8.1.2 it also changes the conversion and reads right.

"Read as" means we forced the matrix in a decode; we did not test real players.
