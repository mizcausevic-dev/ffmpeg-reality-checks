### Description

You put a short clip over a longer one with the overlay filter, and when the short clip ends it does not disappear: it freezes on its last frame. Why, and how do you stop it? We overlay a 2 second synthetic clip with a frame counter on a 5 second base, and measure every output frame for eof_action repeat (the default), endall, pass, repeatlast=0, shortest=1 and enable='lt(t,2)'.

Clips (lavfi, lossless x264, mkv, 25 fps, yuv420p): a base of 125 frames (5 s, 96x72) where frame n is flat luma 16+n, and an overlay of 50 frames (2 s, 32x24) where frame m is flat luma 186+m, a counter from 0 to 49. The overlay sits at x=56, y=4. So a pixel in the overlay square names the overlay frame, and a pixel outside it names the base frame. No frame hash is shared between the clips.

Readers: ffmpeg framemd5 of a crop of the output (the overlay square), each hash looked up in the same crop of the source clips, and raw decoded planes read in Node (mean luma and chroma inside the square, flatness outside). They name the same thing for every output frame of all 10 outputs, and the picture outside the square is always base frame i.

Control: a base cut to 2 s, the same length as the overlay, gives 50 frames, the counter 0 to 49 once each, and no freeze. Known positive: the default (no eof_action at all, identical frame for frame to eof_action=repeat) gives 125 frames, 5 s: the counter climbs to 49 at output frame 49 and counter 49 then stays on screen for 76 frames to the end. 75 of them, 3 s, are the freeze, and the base keeps playing underneath.

eof_action=endall and shortest=1 end the whole output when the overlay ends: 50 frames, 2 s. The freeze is gone, but 75 frames (3 s) of the base are cut off with it.

eof_action=pass, repeatlast=0 and enable='lt(t,2)' keep the base: 125 frames, 5 s, the overlay plays counters 0 to 49 and then is gone, and the 75 frames after it are base only. The three outputs are identical, hash for hash.

A late overlay (delayed 1 s with setpts=PTS+1/TB): the base plays alone for 25 frames, the overlay starts at output frame 25, and with the default it still freezes on counter 49 to the end, counter 49 on 51 frames (50 of them frozen). With eof_action=pass it plays 50 frames and leaves at output frame 75.

The 12 tests pass on ffmpeg 6.1.1 and 8.1.2. The exact counts are asserted on 6.1.1 only; on other builds the tests assert relations (the default repeats, endall is no longer than the overlay, pass is as long as the base), which also pass on 8.1.2.
